# Этап 3: фронтенд и гостевой режим — дизайн

Дата: 2026-10-18
Статус: согласован в чате, ждёт проверки спецификации
Основная спецификация: `docs/specs/2026-10-15-gost-formatter-design.md`

## 1. Цель

Веб-интерфейс поверх API этапа 2: человек загружает документ или текст,
выбирает ГОСТ или свои требования, получает результат. Первый документ можно
обработать без регистрации.

**Критерии успеха**

- Гость без регистрации проходит мастер: текст → «Проверить» → видит замечания
  и скачивает DOCX.
- Пользователь регистрируется, создаёт профиль на основе ГОСТа, меняет поле,
  запускает «Оформить» по своему профилю; гостевые задачи переносятся в аккаунт.
- Новое правило в профиле бэкенда не ломает форму.

## 2. Решения из обсуждения

| Вопрос | Решение |
|---|---|
| Стиль | Минималистичный инструмент, почти без маркетинга |
| Основной экран | Пошаговый мастер: документ → требования → результат |
| Вход | Первый документ без регистрации (гостевой режим) |
| Лимиты гостя | 3 задачи в сутки на гостевую сессию, 10 в сутки на IP |
| Что доступно гостю | Только ГОСТ-профили; файлы хранятся 24 часа |
| После регистрации | Гостевые задачи переносятся в аккаунт |

## 3. Экраны

**Шапка** на всех страницах: логотип; справа «Мои документы», «Мои профили»
(после входа), «Войти» или email с выходом.

**Мастер `/`** — одна строка о сервисе над карточкой мастера.

1. **Документ** (`?step=1`): вкладки «Загрузить DOCX» (drag-and-drop, до 20 МБ,
   проверка размера и расширения на клиенте) и «Вставить текст». «Далее»
   активна, когда есть файл или непустой текст.
2. **Требования** (`?step=2`): список профилей — сначала ГОСТы, потом свои.
   Ссылка «Настроить свои требования» → редактор → после сохранения возврат
   в мастер с выбранным профилем; гостю вместо неё «Свои требования — после
   регистрации». Режим: карточки «Проверить — оставим комментарии» и
   «Оформить — исправим сами». Кнопка «Запустить».
3. **Результат** `/jobs/{id}`: пока обработка — «Обрабатываем…», опрос статуса
   каждые 2 с. Готово — сводка («12 замечаний: 9 исправлено, 3 требуют вашего
   решения»), список замечаний по правилам с пунктом ГОСТа, справа
   PDF-предпросмотр (`<iframe>`), кнопки «Скачать DOCX», «Скачать PDF»,
   «Проверить другой документ». Ошибка — текст от API и «Попробовать снова».
   Гостю — плашка «Результат хранится 24 часа — зарегистрируйтесь, чтобы
   сохранить».

Файл держится только в памяти страницы: перезагрузка на шаге 2 возвращает на
шаг 1. Кнопка «Назад» браузера работает по `?step`.

**Остальные страницы**

- `/login`, `/register` — простые формы; после входа возврат по `?next=`.
- `/documents` — история задач: дата, профиль, режим, статус, срок хранения.
- `/profiles` — свои профили, «Создать на основе ГОСТа», «Импорт».
- `/profiles/{id}` — редактор профиля (раздел 4).

## 4. Редактор профиля

- Сверху: название (редактируемое), «на основе ГОСТ 7.32-2017», кнопки
  «Сохранить», «Экспорт JSON», «Удалить».
- Слева — оглавление из 10 групп (Страница, Основной текст, Заголовки,
  Структура, Нумерация страниц, Рисунки и таблицы, Формулы, Списки, Источники,
  Типографика); точка у группы с отличиями от ГОСТа. Справа — поля группы.
- Строка правила: переключатель «проверять» (`enabled`), подпись, поле со
  значением и единицами, под ним серым «по ГОСТ: 30 мм, п. 6.1.1». Отличие от
  ГОСТа — подсветка строки и ссылка «вернуть как в ГОСТе».
- Типы полей: число со степпером и пределами, выпадающий список, переключатель.
- Описание полей — словарь на фронтенде: ключ правила и путь внутри `value` →
  группа, подпись, тип, единицы, пределы. Правила без описания показываются в
  группе «Другое» как JSON только для чтения.
- «Сохранить» отправляет весь профиль (`PUT /profiles/{id}`); ошибка API —
  над формой. Уход со страницы с несохранёнными изменениями — подтверждение.
- ГОСТ-профили открываются только для просмотра, сверху «Создать свой на
  основе».

## 5. Гостевой режим в API

- Запрос к `POST /jobs` или `GET /jobs/*` без входа создаёт гостевую сессию
  (таблица `guest_sessions`: id, token_hash, created_at, expires_at; cookie
  `guest`, httpOnly, SameSite=Lax, 24 ч). `jobs.user_id` становится
  необязательным, добавляется `jobs.guest_id`.
- Гость видит только задачи своей гостевой сессии; чужие → 404.
- Лимиты: 3 задачи за последние 24 часа на гостевую сессию, 10 на IP
  (считаются по таблице задач; в `jobs` добавляется `client_ip`). Превышение →
  429 «Зарегистрируйтесь, чтобы продолжить».
- IP: из `X-Forwarded-For` только если адрес подключения входит в
  `TRUSTED_PROXIES` (список CIDR через запятую), иначе адрес подключения.
- Гостю — только ГОСТ-профили (свой → 404); `expires_at` = +24 ч.
- Регистрация или вход с cookie `guest`: задачи гостя получают `user_id`,
  `guest_id` обнуляется, срок хранения продлевается до `FILE_TTL_DAYS`,
  гостевая сессия удаляется, cookie стирается.
- `GET /auth/me` для гостя → 401 (как сейчас); фронтенд узнаёт о гостевом
  статусе по 401 и показывает гостевой интерфейс.
- Очистка (`cleanup`) удаляет просроченные гостевые сессии.

## 6. Стек и устройство фронтенда

- Next.js (App Router, TypeScript), Tailwind; свои компоненты без UI-библиотек
  (кнопка, поле, переключатель, вкладки, шаги, плашка ошибки, список).
- Стиль: шрифт Inter, один акцентный цвет, светлая тема; позже — тёмная по
  системной настройке. Без градиентов и теней, тонкие разделители.
- Next.js проксирует `/api/*` на FastAPI (`API_URL`), cookie на одном домене,
  без CORS.
- Тексты интерфейса — по-русски; ошибки API показываются как есть (они уже
  русские).

## 7. Тестирование

- API: pytest — изоляция гостей (гость ↔ гость, гость ↔ пользователь), лимиты
  по сессии и IP, доверенный прокси, перенос задач при регистрации и входе,
  24 часа хранения, запрет своих профилей.
- Фронтенд: Vitest + Testing Library — шаги мастера, словарь полей, подсветка
  отличий, обработка ошибок API.
- Сквозные: Playwright против запущенных API и фронтенда (SQLite, Redis,
  подменённый LibreOffice): сценарий гостя и сценарий пользователя из раздела 1.
- CI: отдельный workflow фронтенда — lint, typecheck, vitest, build, Playwright.

## 8. Порядок работ

1. Гостевой режим в API.
2. Каркас Next.js, дизайн-токены, базовые компоненты, прокси к API.
3. Вход и регистрация.
4. Мастер.
5. Профили и редактор.
6. История документов.
7. Сквозные тесты и CI.

## 9. Вне этапа

- Тёмная тема, мобильная вёрстка сложнее «одна колонка».
- Извлечение требований из методички, оплата, вход через Яндекс/VK.
