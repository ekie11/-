# Telegram-бот и вход через Telegram — дизайн

Дата: 2026-10-22
Статус: согласован в чате, ждёт проверки спецификации
Основные спецификации: `docs/specs/2026-10-15-gost-formatter-design.md`,
`docs/specs/2026-10-18-frontend-design.md`, `docs/specs/2026-10-19-guideline-extraction-design.md`

## 1. Цель

Сервис доступен как бот в Telegram: студент присылает документ и получает
оформленный DOCX, PDF и замечания, не заходя на сайт. В боте доступны свои
профили и «Создать профиль из методички». Один и тот же человек в боте и на
сайте — один аккаунт (по Telegram ID).

**Критерии успеха**

- Новый пользователь пишет боту → присылает DOCX → выбирает ГОСТ и режим →
  через минуту получает DOCX, PDF и сводку замечаний.
- Профиль, созданный в боте из методички, виден на сайте после «Войти через
  Telegram», и наоборот.
- Без `TELEGRAM_BOT_TOKEN` сайт работает как раньше; бот и кнопка выключены.

## 2. Решения из обсуждения

| Вопрос | Решение |
|---|---|
| Возможности бота | оформление/проверка, свои профили, история, профиль из методички |
| Связка аккаунтов | вход через Telegram на сайте (виджет Telegram Login); аккаунт = Telegram ID |
| Пользователь бота без сайта | аккаунт создаётся автоматически по Telegram ID |
| Домен для виджета | туннель Tuna с постоянным поддоменом, https; `COOKIE_SECURE=true` |
| Архитектура | бот — отдельный контейнер, ходит в существующий API по внутренней сети |
| Получение сообщений | long polling (внешний адрес боту не нужен) |
| Библиотека | aiogram 3 |

## 3. API и база

### 3.1 Пользователь

- `users.telegram_id` — BigInteger, unique, nullable; `users.telegram_name` —
  String(255), nullable (имя для шапки сайта).
- `users.email` и `users.password_hash` становятся nullable (у пользователя
  бота их нет). Вход по почте для таких пользователей невозможен (нет пароля).
- Alembic-миграция `0005_telegram`.
- `GET /auth/me` возвращает `{id, email | null, telegram_name | null,
  telegram_linked: bool}`.

### 3.2 Вход бота

- Запрос с заголовками `X-Bot-Secret` и `X-Telegram-User: <id>` (и необязательным
  `X-Telegram-Name`) аутентифицирует пользователя с этим `telegram_id`; если его
  нет — создаётся (`email=NULL`, `password_hash=NULL`).
- Проверка: `BOT_API_SECRET` непустой и совпадает (`hmac.compare_digest`),
  `X-Telegram-User` — положительное целое; иначе 401.
- Реализуется в существующей зависимости `current_user` (и опциональном
  варианте): сначала заголовки бота, затем cookie сессии. Все эндпоинты задач,
  профилей, извлечений работают для бота без изменений. Гостевой режим для
  запросов бота не используется.
- Caddy удаляет `X-Bot-Secret`, `X-Telegram-User`, `X-Telegram-Name` из всех
  внешних запросов (`request_header -X-Bot-Secret` и т.д.).

### 3.3 Вход через Telegram на сайте

- `POST /auth/telegram` — тело: данные виджета (`id, first_name, last_name?,
  username?, photo_url?, auth_date, hash`). Проверка по алгоритму Telegram:
  `secret = SHA256(TELEGRAM_BOT_TOKEN)`, `data_check_string` — поля кроме `hash`,
  отсортированные, `key=value` через `\n`; `hash == HMAC_SHA256(secret,
  data_check_string)` (`compare_digest`); `auth_date` не старше 86400 с.
  Неверно → 401 «Не удалось подтвердить вход через Telegram».
- Найден пользователь с `telegram_id` → сессия (как обычный вход); нет → новый
  пользователь + сессия. Гостевые задачи переносятся (как при обычном входе).
  `telegram_name` обновляется из `first_name` (+ `last_name`).
- `POST /auth/telegram/link` (вошедший пользователь) — те же данные и проверка;
  ставит `telegram_id` текущему пользователю. Занят другим аккаунтом → 409
  «Этот Telegram уже привязан к другому аккаунту».
- `GET /config` (публичный) → `{telegram_bot_username | null}` — для кнопки и
  ссылки на бота.

### 3.4 Настройки (`.env`)

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `BOT_API_SECRET`
(`openssl rand -hex 32`). Нет токена — `/auth/telegram*` отвечают 503, `GET
/config` отдаёт `null`, контейнер бота завершается с сообщением в лог.

## 4. Бот

### 4.1 Устройство

- Пакет `backend/gostdoc_bot/`: `main.py` (запуск polling), `api.py` (клиент API
  на httpx с заголовками бота; `API_URL=http://api:8000`), `handlers/`
  (меню, оформление, профили, история, методичка), `texts.py` (все тексты),
  `keyboards.py`.
- Состояние диалога — aiogram FSM в Redis (`RedisStorage`), TTL 1 ч.
- Файлы из Telegram скачиваются в память, отправляются в API и не сохраняются.
  Лимит Telegram на скачивание ботом — 20 МБ: больше → «Файл больше 20 МБ».
- Ожидание задачи — опрос `GET /jobs/{id}` / `GET /extractions/{id}` каждые 2 с,
  редактирование одного сообщения со статусом; общий таймаут — как у задач.

### 4.2 Диалоги

- **Меню** (`/start`, кнопка «Меню»): «Оформить документ», «Мои профили»,
  «Создать профиль из методички», «История», «Помощь».
- **Оформить документ:** «Пришлите DOCX-файл или вставьте текст сообщением» →
  текст можно несколькими сообщениями, затем «Готово» → кнопки профилей
  (ГОСТы, затем свои) → «Проверить — оставим комментарии» / «Оформить —
  исправим сами» → «Обрабатываем…» → сводка («12 замечаний: 9 исправлено,
  3 требуют вашего решения»), первые 10 замечаний текстом, файлы DOCX и PDF,
  кнопка «Все замечания на сайте» (ссылка `SITE_URL/jobs/{id}`, если задан
  `SITE_URL`).
- **Мои профили:** список; у каждого «Использовать» (переход к шагу «пришлите
  документ» с выбранным профилем), «Скачать JSON», «Открыть на сайте».
- **История:** 5 последних задач (дата, профиль, режим, статус) с кнопкой
  «Скачать DOCX»/«Скачать PDF» для готовых и не истёкших.
- **Создать профиль из методички:** файл DOCX/PDF или текст → базовый ГОСТ
  (по умолчанию ГОСТ 7.32-2017) → «В очереди…» / «Читаем методичку…» →
  список найденного (требование: значение — «цитата» (стр.)), кнопки ✅/⬜ на
  строку, по 8 строк на страницу с «‹ ›»; блок «Не поддерживается» текстом →
  «Создать профиль» → «Как назвать профиль? («-» — по имени файла)» →
  «Профиль создан» + «Использовать сейчас» / «Открыть на сайте». Функция
  выключена в API → кнопка меню скрыта.
- **Помощь:** что умеет бот, лимиты, ссылка на сайт.
- **Ошибки:** текст `detail` из API; под ним «В меню». Сетевые ошибки API —
  «Сервис временно недоступен, попробуйте позже».

## 5. Сайт

- `/login`, `/register`: кнопка «Войти через Telegram» (виджет
  `telegram-widget.js`, `data-onauth` → `POST /api/auth/telegram`), если
  `GET /config` вернул `telegram_bot_username`.
- Шапка: имя из Telegram, если нет email.
- Страница `/account`: email или Telegram; «Привязать Telegram» (виджет →
  `POST /auth/telegram/link`), если не привязан.
- Главная: строка «Бот в Telegram: @имя» со ссылкой.

## 6. Деплой

- `docker-compose.yml`: сервис `bot` (образ бэкенда, `python -m gostdoc_bot`,
  env: `TELEGRAM_BOT_TOKEN`, `BOT_API_SECRET`, `API_URL`, `REDIS_URL`,
  `SITE_URL`; depends_on api/redis; `restart: unless-stopped`); `api` получает
  `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `BOT_API_SECRET`.
- `Caddyfile`: удаление заголовков бота у входящих запросов.
- `DEPLOY.md`: создание бота у @BotFather; туннель Tuna с постоянным поддоменом
  на порт 80; `/setdomain` у @BotFather на этот поддомен; `SITE_URL`;
  `COOKIE_SECURE=true`; запуск на Mac/Windows (Docker Desktop, отключить сон).
- `.env.example`: новые переменные без значений.

## 7. Тестирование

- API: вход бота (автосоздание, повторный — тот же пользователь, неверный/пустой
  секрет → 401, нечисловой ID → 401); подпись виджета (верная, подделанная,
  просроченная); `/auth/telegram` создаёт/находит пользователя и переносит
  гостевые задачи; `/link` (успех, 409); `/auth/me` для пользователя без email;
  миграция 0005 вверх/вниз; без токена → 503.
- Caddy: конфиг содержит удаление трёх заголовков (тест чтения Caddyfile).
- Бот: сценарии с подменённым API (respx/транспорт httpx) и aiogram-тестовым
  диспетчером: оформление (файл → профиль → режим → результат), текст из
  нескольких сообщений, методичка (переключатели, страницы, создание),
  ошибка лимита, файл > 20 МБ.
- Фронтенд: кнопка видна/скрыта по `/config`; обработчик ответа виджета
  вызывает API и перенаправляет; `/account` привязка и 409.
- Живая проверка — пользователем по инструкции из DEPLOY.md.

## 8. Порядок работ

1. Пользователь с Telegram ID, вход бота по секрету, Caddy, `/config`.
2. Вход и привязка через виджет (API).
3. Каркас бота: клиент API, меню, оформление документа.
4. Бот: профили, история, методичка.
5. Сайт: кнопка, `/account`, шапка, ссылка на бота.
6. Деплой: compose, DEPLOY.md, `.env.example`.

## 9. Вне этапа

Оплата в боте, inline-режим, групповые чаты, уведомления о готовности после
закрытия чата, правка полей профиля в боте.
