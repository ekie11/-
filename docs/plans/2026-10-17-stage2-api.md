# Этап 2: API, авторизация, профили, очередь задач — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTTP-API на FastAPI поверх движка этапа 1: регистрация и вход, профили требований в базе, загрузка документа или текста, обработка в фоновой очереди, скачивание DOCX, PDF и отчёта.

**Architecture:** Новый пакет `backend/gostdoc_api/` рядом с `gostdoc_engine/`. SQLAlchemy 2 + Alembic (PostgreSQL в проде, SQLite в тестах), RQ + Redis для задач (в тестах — fakeredis и синхронное выполнение), файлы — в локальном каталоге `STORAGE_DIR`. Воркер вызывает `gostdoc_engine.pipeline.process`, затем LibreOffice делает PDF.

**Tech Stack:** Python 3.12+, FastAPI, Uvicorn, SQLAlchemy 2, Alembic, argon2-cffi, RQ, Redis (fakeredis в тестах), httpx (TestClient), LibreOffice headless.

**Spec:** `docs/specs/2026-10-15-gost-formatter-design.md` (разделы 3, 4, 5 «Ошибки», 6).

## Global Constraints

- Код API — `backend/gostdoc_api/`, тесты — `backend/tests/api/`. Движок не меняется, кроме пунктов, явно названных в задачах.
- Все сообщения об ошибках для пользователя — по-русски, в JSON `{"detail": "..."}`.
- Настройки только из переменных окружения: `DATABASE_URL`, `REDIS_URL`, `STORAGE_DIR`, `SECRET_KEY`, `COOKIE_SECURE` (по умолчанию `true`), `SOFFICE_PATH` (по умолчанию `soffice`), `JOB_TIMEOUT_S` (по умолчанию `120`), `FILE_TTL_DAYS` (по умолчанию `30`).
- Пароли — argon2 (`argon2-cffi`), минимум 8 символов. Email приводится к нижнему регистру, уникален.
- Сессия — случайный токен (32 байта, `secrets.token_urlsafe`) в httpOnly-cookie `session`, `SameSite=Lax`; в БД хранится только SHA-256 токена. Срок — 30 дней.
- Пользователь видит и меняет только свои профили и задачи; чужой id → 404 (не 403).
- ГОСТ-профили (`readonly`) нельзя изменить или удалить → 403 «Готовый ГОСТ-профиль нельзя изменить — создайте свой на его основе».
- Вход: DOCX до 20 МБ или текст; проверка размера и формата — до постановки в очередь (те же `InputError` движка) → 400.
- Таймаут задачи — `JOB_TIMEOUT_S`; при таймауте или исключении — статус `error` и русское сообщение; задача никогда не остаётся в `running`.
- Задача хранит `profile_snapshot` — копию профиля на момент запуска.
- Файлы задачи удаляются через `FILE_TTL_DAYS`; запись задачи остаётся со статусом `expired`.
- Тесты не требуют Postgres, Redis и LibreOffice: SQLite в памяти/файле, fakeredis + `Queue(is_async=False)`, LibreOffice подменяется в тестах (кроме одного теста, помеченного `@pytest.mark.soffice`, пропускаемого без `soffice`).

## Review Focus

1. **Чужие данные** — пользователь A запрашивает профиль/задачу/файл пользователя B по id → 404, не утечка. Тест в задачах 3 и 5.
2. **Падение воркера посреди задачи** (исключение движка, `TextChangedError`, таймаут LibreOffice) — статус `error` с понятным текстом, DOCX без PDF не теряется. Тест в задаче 5.
3. **Профиль удалён или изменён после запуска задачи** — задача доделывается по снимку. Тест в задаче 5.
4. **Импорт битого JSON профиля / профиля с неизвестным ключом** — 400 с русским сообщением, не 500. Тест в задаче 3.
5. **Повторный вход и выход** — после logout старый cookie не работает; неверный пароль и несуществующий email дают одинаковый ответ. Тест в задаче 2.

### Task 5: Задачи обработки и воркер

**Files:**
- Create: `backend/gostdoc_api/queue.py`, `backend/gostdoc_api/worker.py`, `backend/gostdoc_api/routes/jobs.py`, `backend/tests/api/test_jobs.py`

**Interfaces:**
- Consumes: `gostdoc_engine.pipeline.process`, `ProcessResult`, `TextChangedError`; `gostdoc_engine.importer.load_docx`, `InputError`, `MAX_BYTES`; `resolve_profile`; `storage.*`; `render_pdf`, `PdfError`.
- Produces:
  - `queue.get_queue(settings) -> rq.Queue` (зависимость; в тестах — fakeredis, `is_async=False`).
  - `worker.run_job(job_id: str) -> None` — открывает свою сессию БД по `get_settings()`; `running` → `process(input, Profile.model_validate(snapshot), mode)` → пишет `result.docx`, `report` → `render_pdf` (при `PdfError` — `output_pdf=None`, в `report["warnings"]` строка «PDF-предпросмотр недоступен») → `done`. `InputError`/`TextChangedError`/любое исключение → `error` и сообщение: для `InputError` — его текст, для `TextChangedError` — «Обработка остановлена: оформление затронуло бы текст работы. Попробуйте режим «Проверить».», иначе «Не удалось обработать документ, попробуйте ещё раз». Задача ставится в очередь с `job_timeout=JOB_TIMEOUT_S`; RQ при таймауте вызывает `on_failure` → тот же перевод в `error` с текстом «Обработка заняла слишком много времени».
  - `POST /jobs` (multipart: `file` **или** `text`, `profile_id`, `mode` ∈ `check|format`) → 202 `{id, status}`. Проверки до очереди: ровно одно из `file`/`text` → иначе 400 «Загрузите файл или вставьте текст»; файл: размер и `load_docx` → 400 с текстом `InputError`; текст: пустой → 400 «Текст пустой — вставьте текст работы»; профиль не найден → 404; `expires_at = now + FILE_TTL_DAYS`.
  - `GET /jobs` → свои задачи (новые сверху): `{id, status, mode, profile_name, created_at, expires_at}`.
  - `GET /jobs/{id}` → `{id, status, mode, error, report, has_pdf, created_at, expires_at}`.
  - `GET /jobs/{id}/docx`, `/pdf` → файл (`application/vnd.openxmlformats-officedocument.wordprocessingml.document` / `application/pdf`, имя `result.docx`/`result.pdf`); если задача не `done` или файла нет → 409 «Результат ещё не готов» / 404 для PDF без предпросмотра; `expired` → 410 «Срок хранения файла истёк».
