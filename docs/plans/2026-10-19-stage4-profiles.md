**Spec:** `docs/specs/2026-10-15-gost-formatter-design.md` (разделы 4, 9 «этап 4»); решения этого этапа согласованы в чате и записаны ниже.

## Решения этапа (согласованы в чате)

- Профили: `gost-2.105-2019` («ГОСТ 2.105-2019 — Текстовые документы»), `espd-19.106-78` («ЕСПД, ГОСТ 19.106-78 — Программные документы»). Рамки и основная надпись (ГОСТ 2.104), лист регистрации изменений — не проверяются.
- Значения брать из текстов стандартов; если значение не удаётся подтвердить — оставить разумное значение и `"source": "требует сверки: <что именно>"`. Отдельный список таких мест — в отчёте задачи.
- Список литературы: проверка записей + автоисправление только типографики; записи не переписываются (порядок элементов не меняется).
- Ссылки в тексте: формат `[N]`, `[N, с. X]`, `[N; M]`, `[N–M]`.

## Global Constraints

- Новый ключ правила `bibliography` добавляется в `KNOWN_RULE_KEYS`; значение:
  `{"standard": "7.0.100-2018", "order": "alphabetical" | "mention", "citation_format": "[N]"}`; `severity: "error"`, источник «ГОСТ Р 7.0.100-2018; ГОСТ 7.32-2017, п. 6.16».
- Профиль 7.32 получает правило `bibliography` с `order: "mention"`; 2.105 и ЕСПД — тоже (`order: "mention"`).
- Неизменность слов: инвариант `textguard` действует; в записях источников автоматически меняются только тире и пробелы вокруг « — », « // », « : », « ; ». Устаревшее «[Электронный ресурс]» не заменяется (это слова) — только замечание «Используйте «Текст : электронный» (ГОСТ Р 7.0.100-2018)».
- Все сообщения — по-русски, с номером записи: «Источник 3: нет года издания».
- Правило не падает на документах без раздела источников: если раздела нет — одно замечание «Не найден раздел «Список использованных источников»» (severity `recommendation`), если в тексте есть ссылки `[N]`; иначе ничего.

## Review Focus

1. Документ без списка источников и без ссылок — ноль замечаний от `bibliography`. Тест в задаче 3.
2. Запись источника, разбитая на несколько абзацев (перенос строки внутри записи) — считается одной записью, если следующий абзац не начинается с номера. Тест в задаче 3.
3. Ссылка `[12]` на несуществующий номер и источник, на который нет ссылок — по одному понятному замечанию. Тест в задаче 4.
4. Повторный «Оформить» идемпотентен с новым правилом — ноль новых замечаний и без изменения слов. Тест в задаче 4.
5. Редактор открывает новые профили без «Другое»-полей (все листья описаны). Тест в задаче 5.

### Task 3: Правило `bibliography` — разбор и проверка записей

**Files:** Create `backend/gostdoc_engine/bibliography.py` (разбор), `backend/gostdoc_engine/rules/bibliography.py`, `backend/tests/test_bibliography_parse.py`, `backend/tests/test_rules_bibliography.py`; Modify `profile.py` (`KNOWN_RULE_KEYS`), три JSON-профиля (добавить правило), `rules/__init__.py`, `tests/builders.py` (блок `("source", text)` — абзац списка источников с нумерацией «N. »).

**Interfaces:**
- `bibliography.find_section(model) -> list[DocParagraph] | None` — абзацы после STRUCTURAL «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» (также «СПИСОК ЛИТЕРАТУРЫ», «БИБЛИОГРАФИЧЕСКИЙ СПИСОК») до следующего STRUCTURAL.
- `@dataclass Entry(number: int | None, text: str, paragraph_index: int)`; `parse_entries(paragraphs) -> list[Entry]` — новая запись начинается с `^\d+[.)]\s` или с элемента списка Word; иначе абзац приклеивается к предыдущей записи.
- `check_entry(entry) -> list[str]` — сообщения: нет года (`\b(1[89]|20)\d{2}\b`), у электронного (`URL:`/`http`) нет «(дата обращения: дд.мм.гггг)», нет области выходных данных (« — » + место/издательство или « // » для статьи), нумерация не по порядку.
- Правило `bibliography` (`fixable=True` только для типографики — задача 4; здесь `check`).

### Task 4: Ссылки в тексте и типографика записей

**Files:** Modify `rules/bibliography.py`, `bibliography.py`; tests в `test_rules_bibliography.py`, `test_pipeline.py`.

**Interfaces:**
- `find_citations(model) -> list[tuple[int, list[int]]]` — (paragraph_index, номера) для `[N]`, `[N, с. X]`, `[N; M]`, `[N–M]` (диапазон раскрывается) вне раздела источников.
